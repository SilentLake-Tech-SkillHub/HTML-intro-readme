# 执行流程

## 1. 项目盘点与事实表

先读用户指定项目和适用 AGENTS.md。寻找现有定稿、设计方案、HTML、构建脚本和检查记录；最新明确要求优先，已有工作继续沿用。

从 README / SKILL / 官方安装说明抽取：定位、适用范围、需要的 Agent 能力、获取地址、完整安装目录、确认加载方式、启动输入、输出目录与打开方式。记录来源 commit、版本、核验日期及图片来源和 SHA-256。只读核验原项目不等于获准修改它。

用户已有明确方案时直接实施。只有缺失的信息会改变执行结果时才问，不为常规配色、实现或本地文件操作反复索要确认。

## 2. 分镜与文案

每屏有稳定 `key`，顺序通过列表表达，锚点按 key 查找。重排时安装、启动、评分链接不再依赖旧页码。

| 字段 | 用途 |
|---|---|
| key / nav | 稳定标识 / 用户看到的章节名 |
| seconds | 标准速度停留秒数 |
| headline / sub | 一句主话 / 一段解释 |
| elements | 图、标签、卡片、表格、提示词的内容和入场秒数 |
| cue | 引出实际下一段，通常在结束前约 1.7 秒出现 |

新手介绍要说清获取 → 安装完整包 → 确认加载 → 提供项目或链接与范围 → 启动 → 成品入口。有账号登录的工作流由用户本人登录；本地材料路径单独说明。用户级和项目级安装路径分列，未知工具路径以其文档为准。

安装提示词写清仓库、安装范围、完整目录、名称、完成后的路径与版本反馈。启动提示词写清项目、输入链接或本地路径、成果目录、本次范围。两段都应可直接复制，按钮不能复制旧版提示词。

已定稿文案作为唯一文本来源，保留版本与变更范围。重排时同步导航、实际播放、过渡词、锚点、目录、时长数据和说明文件，不顺带改正文。

## 3. 画面与实现

先做完整内容，再调排版，最后加入入场与过渡。优先真实截图、清晰路径表和可复制提示词。仅有装饰效果却缺少安装、启动或结果说明，不算完成。

采用数据驱动分镜，素材、文案与播放器分开维护。浏览器直接打开，避免为了静态介绍引入服务端。细节见 quality-standard.md。

## 4. 离线打包

将 CSS、JS、截图、图标、字体与必要指南全部内嵌。打包器不自动解析 JS 动态 import / fetch；先完成静态构建，浏览器断网验证为最终证据。

打包脚本使用 Python 3.9+ 标准库。浏览器检查使用 Node.js 18+、可用的 Playwright / playwright-core 与 Chromium 浏览器；依赖路径通过参数传入，不绑定作者机器。

```bash
python3 scripts/bundle_html.py /项目/index.html --output /项目/项目介绍.html --page guide.html --page assets/icons/LICENSE.txt
```

该命令只读本地输入，输出单文件和素材哈希清单；`--page` 可重复，用于 HTML 指南或文本许可。指南的“返回入口”自动关闭内嵌弹窗。外部仓库链接保留为用户主动点击的链接。CSS @import、响应式 srcset 和动态模块先展开为静态资源再打包。

只保留一个当前离线入口。旧版移入历史目录，保留恢复资料。用户要求桌面文件夹时，将入口、指南、图片、源码、定稿和检查记录放在该目录，启动器使用本机实际浏览器。

## 5. HTML 浏览器验收与交付、同步

先检查现有 Node、Playwright 和浏览器，复用本机可用依赖。测试用独立临时浏览器上下文，不使用用户日常浏览器资料。

```bash
node scripts/check_browser.cjs --input /项目/项目介绍.html --out /项目/checks --module /依赖/playwright-core --browser /浏览器可执行文件
```

基础检查器使用 `.scene`、`[data-scene]`、`#pace`、`#play`、`#timeline` 和 `#screen[data-durations]`。适配其他实现时按实际 DOM 修改测试，保留相同可观察结果，不能省掉检查来凑通过。

基础检查器不取代逐字核对、全部时序、提示词剪贴板原文、图片弹窗、全屏和许可链接测试。把完整清单中的结果记为“通过 / 失败 / 未检查”，失败项修复后复查相关范围。

用户要求同步 GitHub 时，核实目标仓库和授权范围，检查差异，只提交本次技能所需文件。新技能仓库可放简短 README 作为公开落地页，入口规则以 SKILL.md 为准。同步后核对远端 SHA 和关键文件，只报告已确认的结果。

## 6. 可选：HTML 完成后的视频导出（用户要求时）

第 5 步的 HTML 制作、验收与交付完成后，默认流程结束。用户要求视频版时，再按 [video-export.md](video-export.md) 调用 `scripts/export_video.cjs`，先导出短片检查，再按需要导出整片；原网页保持不变。核对源版本和哈希，使用同一动画时钟，保留硬件编码的实际状态与耗时证据。完整解码通过后，实际查看每屏抽帧和动效；新增视频目录中交付 MP4、参数与验收记录。发布授权仍单独判断。

## 交付目录建议

```text
项目介绍/
  项目介绍.html            当前离线入口
  index.html / *.css / *.js
  guide.html / Q&A.md       完整说明
  assets/                  图片、图标、许可
  sources/                 来源、分镜、提示词、构建脚本
  动画文案_vX.Y.Z.md
  checks/                  截图、数据、验收报告
  历史版本/
```

评分 PNG 是用户要求评分图时的独立交付物，不为没有评分需求的 README 凭空增加评分。
